LUD-22: Alternative payment methods.
====================================

`author: Francis Pouliot`

---

## Service response

The `payRequest` response MAY include a `payment_methods` field listing supported codes:

```typescript
{
    // ...LUD-06 fields...
    "payment_methods": ["L-BTC", "BTC-SP"]
}
```

Lightning is the LUD-06 default and MUST NOT appear.

### Registered codes

| `code` | Method |
|---|---|
| `L-BTC`  | Liquid Bitcoin |
| `BTC`    | Bitcoin on-chain |
| `BTC-SP` | Bitcoin Silent Payments (BIP-352) |

New codes are added by PR.

## Wallet callback

The wallet MAY add `&payment_method=<code>` to the LUD-06 callback URL.

If the method is unsupported the service silently falls back to standard LUD-06 (BOLT11).

## Service callback response

When `payment_method` is set and supported:

```json
{ "address": string }
```

`address` is whatever address format the requested method requires (a Liquid address for `L-BTC`, a Bitcoin address for `BTC`, a BIP-352 silent-payment address for `BTC-SP`).

## Notes

- `minSendable` / `maxSendable` and the `metadata` description-hash check apply to Lightning only.
- `payment_methods` ordering is not authoritative.
